### 第一步：了解与分析要求

让我们先把题目的核心逻辑提取出来：

1. **基础结构**：我们有一棵包含 $n$ 个节点和 $n-1$ 条“老边”的树。在树的结构中，任意两个节点之间都有且仅有一条简单路径。
    
2. **新增结构**：现在又增加了 $m$ 条“新边”。每一条新边 $(u, v)$ 都会和树上 $u$ 到 $v$ 的原始路径形成一个**环**。
    
3. **目标动作**：我们需要切断**一条老边**和**一条新边**，使得整个图不再联通。
    

**破题关键**：

当我们切断某一条老边 $e$ 时，这棵树原本会被分成两半。但是，因为我们添加了新边，可能会有新边“跨越”了这条被切断的老边，从而让图依然保持联通。

因此，我们可以定义一个概念：**覆盖度**。

一条老边的“覆盖度”，就是指有多少条新边，其两端点在树上的路径经过了这条老边。

- **情况 1：覆盖度为 0**
    
    切断这条老边后，图已经不联通了。此时我们随便切断 $m$ 条新边中的任意一条都可以。所以对于这种老边，有 $m$ 种方法。
    
- **情况 2：覆盖度为 1**
    
    切断这条老边后，只有 $1$ 条新边在维系着图的联通。为了让图不联通，我们**必须且只能**切断这条特定的新边。所以对于这种老边，有 $1$ 种方法。
    
- **情况 3：覆盖度 $\ge 2$**
    
    切断这条老边后，还有至少 $2$ 条新边维系着联通。因为题目限制我们总共只能切断一条新边，所以怎么切都无法让图不联通。这种老边提供 $0$ 种方法。
    

### 第二步：概略介绍解决方案 (树上差分)

如果每次加新边都去遍历路径更新覆盖度，时间复杂度会爆炸。这里就要用到图片标题里提到的终极武器：**树上边差分** 。

假设我们要给节点 $u$ 到节点 $v$ 路径上的所有边加上 1（即增加一次覆盖）：

1. 找到 $u$ 和 $v$ 的最近公共祖先（LCA），我们记为 $lca$。
    
2. 我们在差分数组 `diff` 中做如下操作：
    
    `diff[u]++`
    
    `diff[v]++`
    
    `diff[lca] -= 2`
    
3. 所有新边处理完毕后，我们对这棵树进行一次**自底向上**的深度优先遍历（DFS）。一个节点 $x$ 及其子树的差分值之和，就等于它与它父节点之间的那条老边的覆盖度！

# 1. 树上差分可以维护哪些信息？

## 一、维护点被经过的次数

这是最常见的。

例如有很多条路径：

```
u -> v
```

每条路径经过的所有点都 `+1`，最后问每个点被经过多少次。

典型题：

```
P3128 Max FlowP3258 松鼠的新家LeetCode 旅行价格最小化
```

点差分公式：

```
diff[u]++;diff[v]++;diff[lca(u, v)]--;diff[parent[lca(u, v)]]--;
```

最后 DFS 累加，得到每个点被经过的次数。

---

## 二、维护边被经过的次数

如果关心的是路径经过了哪些边，而不是哪些点，就用边差分。

把一条边的信息放到它下面那个点上。

例如边：

```
parent[x] -- x
```

可以用 `x` 代表这条边。

边差分公式：

```
diff[u]++;diff[v]++;diff[lca(u, v)] -= 2;
```

最后 DFS 累加后，`diff[x]` 就表示边：

```
parent[x] -- x
```

被多少条路径经过。

---

## 三、维护路径上的点权加法

不一定每条路径只加 `1`，也可以加任意值 `w`。

例如：

```
每条路径 u -> v 上的所有点都加 w
```

那么点差分写成：

```
diff[u] += w;diff[v] += w;diff[lca] -= w;diff[parent[lca]] -= w;
```

最后得到每个点被加了多少总权值。

---

## 四、维护路径上的边权加法

类似地，如果每条路径上的所有边都加 `w`：

```
diff[u] += w;diff[v] += w;diff[lca] -= 2 * w;
```

DFS 累加之后，每个非根节点 `x` 的 `diff[x]` 就代表边：

```
parent[x] -- x
```

被加上的总权值。

---

## 五、维护路径覆盖情况

如果你只关心某个点或某条边有没有被路径覆盖过，也可以用差分。

先统计次数：

```
cnt[x]
```

最后判断：

```
cnt[x] > 0
```

就表示这个点或这条边被至少一条路径覆盖。

例如：

```
哪些边被至少一条路径经过？哪些点被至少访问一次？
```

---

## 六、维护路径经过次数的奇偶性

有时候不关心经过多少次，只关心经过次数是奇数还是偶数。

可以用异或思想。

例如每条路径经过的点都翻转一次，最后判断每个点被翻转了几次的奇偶。

这种情况下可以用：

```
diff[u] ^= 1;diff[v] ^= 1;diff[lca] ^= 1;diff[parent[lca]] ^= 1;
```

或者对于边：

```
diff[u] ^= 1;diff[v] ^= 1;
```

再通过 DFS 异或累积。

---

## 七、维护路径上的多种类型统计

比如每条路径有一种颜色 `c`，你想统计每个点被每种颜色路径经过多少次。

如果颜色数量不大，可以开多个差分数组：

```
diff[color][u]
```

每种颜色单独做一次树上差分。

如果颜色很多，就需要用 map、unordered_map 或其他离线技巧。

本质仍然是：

```
对路径上的点或边累加某种贡献
```

---

## 八、维护路径贡献后的总代价

很多题不是直接问经过次数，而是经过次数乘以点权或边权。

例如某个点价格是：

```
price[i]
```

它被经过：

```
cnt[i]
```

次，那么它对总答案的贡献是：

```
cnt[i] * price[i]
```

这类题中，树上差分负责求 `cnt[i]`，之后再结合点权或边权计算答案。

例如你刚才那道 LeetCode 题：

```
先用树上差分统计每个点被经过次数再用树形 DP 决定哪些点价格减半
```

---

# 2. 这些信息有什么共同点？

它们的共同点非常重要：

## 共同点一：都是“路径贡献”

树上差分适合处理的问题通常长这样：

```
给很多条路径 u -> v每条路径会对路径上的所有点或边产生影响最后问每个点或每条边的总影响
```

例如：

```
每条路径上的点 +1每条路径上的边 +1每条路径上的点 +w每条路径上的边 +w统计覆盖次数统计是否被覆盖统计路径经过频率
```

---

## 共同点二：贡献可以叠加

这是最核心的。

比如：

```
点 x 被第 1 条路径经过，贡献 +1点 x 被第 2 条路径经过，贡献 +1点 x 被第 3 条路径经过，贡献 +1
```

最后就是：

```
总贡献 = 1 + 1 + 1 = 3
```

也就是说，每条路径对一个点或边的影响是可以累加的。

如果贡献不能叠加，树上差分就不好用了。

---

## 共同点三：修改是离线的

树上差分通常适合这种模式：

```
先给出所有路径修改统一做差分最后 DFS 一次求出最终结果
```

它不适合频繁在线询问：

```
加一条路径马上问某个点的值再加一条路径马上问某条边的值
```

这种动态在线问题一般要用树链剖分、线段树、LCT 等数据结构。

---

## 共同点四：需要有“加”和“减”的抵消关系

差分的本质是：

```
在起点加在终点加在 LCA 附近减最后通过 DFS 把影响还原出来
```

所以被维护的信息最好满足：

```
可以加可以减可以累积
```

最常见的是整数加法：

```
+1, -1+w, -w
```

也可以是异或，因为异或可以自己抵消：

```
x ^ x = 0
```

但像下面这些信息就不太适合直接用普通树上差分：

```
路径上的最大值路径上的最小值路径上的中位数路径上第 k 大路径上是否存在某种复杂结构
```

因为这些东西不能简单通过“加减抵消”来还原。

# 3. 一个总结表

|维护内容|用点差分还是边差分|例子|
|---|---|---|
|点被经过次数|点差分|某个点经过了几条路径|
|边被经过次数|边差分|某条边经过了几条路径|
|点权路径加|点差分|路径上每个点加 `w`|
|边权路径加|边差分|路径上每条边加 `w`|
|是否被覆盖|点差分/边差分|最后判断 `cnt > 0`|
|奇偶经过次数|点差分/边差分|用异或维护|
|总花费|点差分/边差分后再计算|`cnt[i] * price[i]`|
|公共边判断|边差分|看哪些边被所有路径经过|

# 4. 一句话理解

树上差分能维护的信息都有一个共同点：

> **它们都是很多条树上路径对点或边产生的、可以累加和抵消的贡献。**

更具体地说：

```
树上差分不关心路径本身怎么走，它关心的是：每条路径给哪些点或边贡献了多少，最后每个点或边累计得到了多少贡献。
```

所以只要一个问题可以转化成：

```
多次路径加法 + 最后统一统计
```

就很可能能用树上差分。
